# Write-up

## 1. Your timings (100 words)
My first working version took approximately 11 to 12 hours to process all 50 files. The final version took approximately 3 h 17 min hours. This was due to initially running an notebook that checked all 80 classes instead of the 5 mentioned in the brief. I changed the structure of the notebook to check every 5th frame instead and cross-referenced checked it with my original run to verify accuracy.
## 2. Your pipeline (150 words)
The script reads the settings and opens each Parquet file with PyArrow, where It reads the mp4 column row by row and gives every video a file-and-row ID so that the results can be matched back to the original input. Each video is then decoded using AV, which shows all of the seconds accurately starting from the 1st frame, applies the required rotation mentioned in the brief, and places the selected frames into batches. A queue is used to send these batches to the GPU worker(for me 2) running the YOLOv11 model, where FP16 inference is used for the five required classes, all of the detections are mentioned in an single line in the json file and an error is given if failed. After processing is done, all of the json files are merged into final results.jsonl file.
## 3. Where the time goes (150 words)
Most of the processing was focused on YOLOv11 inference model being used in the runtime, as shown by the attached yolo.pt model in the repo, i was able to measure this by using counters, it was focused on understanding the actual compute being used in kaggle due to the limited hours that are available to me, every few seconds, the time spent, decoded batches, processed frames and overall frames per second for both gpu 0 and 1 were being reported, which made it clear that increasing stride(going for every 5th frame instead of the original full), would reduce the inference time needed. AV was ran in another thread so processing was done concurrently and decoding, due to kaggle notebook only having 4 CPU cores, the bottleneck that arose from only have limited cores was also apparent in processing.

## 5. Working with AI (100 words)
One AI suggestion from claude was to run all of the 50 files concurrently, while not dividing the work for processing between the 2 available gpus, resulting in an inefficient and time consuming result. I was able to find this out when i downloaded the file claude initially generated and ran it, but saw that the 2nd gpu was not being used and CPU usage was very high.
## 6. Next steps (100 words)
If I had another week, I would test stride-1 execution with more GPU configurations and compare batch sizes(chunking) for easier processing of chunks. This way I would be able to identify the fastest setup rather than using stride 5(every 5th frame). I would also benchmark PyAV decoding separately to determine whether CPU decoding or GPU inference limits throughput.
